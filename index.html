Question 1

Distinguish between blocking flow and maximum flow in Dinic's Algorithm.

In network flow theory, particularly in Dinic's Algorithm, the concepts of blocking flow and maximum flow represent two entirely different stages of optimization:

Parameter Blocking Flow Maximum Flow
Domain / Scope Defined strictly inside the layered Level Graph $G_L$ of the current phase. Defined globally across the entire flow network $G = (V, E)$.
Core Condition Every directed path from source $S$ to sink $T$ in $G_L$ contains at least one saturated (bottleneck) edge. No further augmenting path can be found using only forward level edges. No augmenting path of any length exists from $S$ to $T$ in the full residual graph $G_f$.
Global Optimality Not necessarily optimal. A blocking flow is only a local saturation of current shortest paths. Longer augmenting paths may still exist. Globally optimal. By the Max-Flow Min-Cut theorem, the flow value is strictly maximal.
Role in Dinic's Sub-routine executed in each iteration using DFS. Each blocking flow pushes the source-to-sink distance up by at least 1. The final termination output after at most $V-1$ phases of finding blocking flows.

Illustration from Course Notes:

Consider $S \to A \to T$ (cap 10, cap 8) and $S \to B \to T$ (cap 5, cap 10). Finding paths saturates $A \to T$ (8 units) and $S \to B$ (5 units). Every shortest path from $S$ to $T$ is now saturated (blocked). This constitutes a blocking flow of $13$ for that layered graph.

Question 2

State any three real-world applications of Minimum Cost Flow algorithms.

Minimum Cost Flow (MCF) determines the most economical way to route a specified volume of flow through a capacity-constrained directed graph. Real-world applications include:

  1. Supply Chain Logistics and Warehouse Distribution: Transporting commercial inventory from regional fulfillment warehouses to retail centers. Nodes represent factories and customer locations, edge capacities denote freight carrier capacity, and edge costs signify fuel, shipping, and toll charges per container (e.g., as noted in the class problem: Amazon routing packages with the lowest fuel expense).
  2. Telecommunication & Content Delivery Network (CDN) Routing: Routing data packets or media streams through internet transit backbones. Vertices are transit routers/switches; capacities prevent link saturation, while costs represent propagation delay or contractual peering cost per gigabit.
  3. Airline Fleet and Crew Scheduling: Assigning aircraft and qualified flight personnel to multi-leg daily flight legs while satisfying flight departure constraints and crew work-hour limitations at minimal lodging and operational overhead.
Question 3

Explain the level graph and blocking flow concepts in Dinic's Algorithm.

Dinic's algorithm improves upon classical Ford-Fulkerson by structuring flow augmentation into synchronized phases consisting of two key primitives:

1. Level Graph ($G_L$) via BFS

A Level Graph is constructed by executing Breadth-First Search (BFS) starting from source node $S$ in the residual graph $G_f$. Every vertex $u$ is assigned a level: $$\text{level}[u] = \text{shortest distance (in edge count) from } S \text{ to } u$$ Pruning Rule: Dinic retains only edges that progress strictly to the adjacent forward level: $$E_L = \{ (u, v) \in E_f \mid \text{level}[v] = \text{level}[u] + 1 \text{ and } c_f(u, v) > 0 \}$$ Edges within the same level ($\text{level}[u] = \text{level}[v]$) or back edges ($\text{level}[v] \le \text{level}[u]$) are eliminated, preventing redundant cycles.

2. Blocking Flow via DFS

Once $G_L$ is formed, multiple augmenting paths of the same minimum length are explored simultaneously using Depth-First Search (DFS). When flow is routed through an edge up to its residual capacity, that edge becomes saturated (residual capacity = 0) and is removed from $G_L$. DFS terminates when no forward path from $S$ to $T$ exists in $G_L$. This combined pushed volume constitutes a Blocking Flow.

Dinic's Algorithmic Convergence:

In each phase, after finding a blocking flow, the distance $\text{level}[T]$ strictly increases: $\text{level}_{i+1}[T] > \text{level}_i[T]$. Thus, Dinic terminates in at most $|V|-1$ phases, yielding an overall worst-case complexity of $\mathcal{O}(V^2 E)$ (compared to Edmonds-Karp's $\mathcal{O}(V E^2)$).

Question 4

Describe the Push-Relabel algorithm and discuss its advantages over augmenting-path methods.

Introduced by Andrew V. Goldberg and Robert Tarjan, the Push-Relabel (Preflow-Push) algorithm departs fundamentally from the augmenting-path paradigm by relaxing the strict global flow conservation during execution.

Preflow & Excess Flow

Instead of maintaining net flow $= 0$ at all intermediate nodes, each node $u \in V \setminus \{S, T\}$ is allowed an excess flow:

$$e(u) = f_{in}(u) - f_{out}(u) \ge 0$$

A vertex with $e(u) > 0$ is called an active vertex.

Height / Label Function

Each vertex has an integer height $h(u)$. Initialized to $h(S) = |V|$, $h(u) = 0$ for all others. Valid labeling requires:

$$h(u) \le h(v) + 1 \quad \text{for every residual edge } (u,v) \in E_f$$

Flow is pushed strictly "downhill", i.e., from height $h(u)$ to $h(u)-1$.

Two Fundamental Operations:

  • Push$(u, v)$: Applicable if $u$ is active ($e(u) > 0$), $c_f(u,v) > 0$, and $h(u) = h(v) + 1$. Push amount $\Delta = \min(e(u), c_f(u, v))$.
  • Relabel$(u)$: Applicable if $u$ is active and for all residual neighbors $(u, v)$, $h(u) \le h(v)$. Increases height: $h(u) = 1 + \min \{ h(v) \mid (u,v) \in E_f \}$.

Advantages over Augmenting-Path Methods (Ford-Fulkerson, Edmonds-Karp):

Feature Augmenting-Path Methods Push-Relabel Algorithm
Search Horizon Global: Searches for complete source-to-sink path across the whole graph per step. Local: Operates strictly on local node neighborhoods via push and relabel.
Parallelizability Difficult: Searching full paths locks large sub-networks. Highly parallelizable: Active nodes can independently push/relabel locally.
Worst-Case Runtime $\mathcal{O}(V E^2)$ for Edmonds-Karp. $\mathcal{O}(V^2 E)$ generic, $\mathcal{O}(V^3)$ FIFO, down to $\mathcal{O}(V^2 \sqrt{E})$ with highest-label selection.
Question 5

Push-Relabel Execution on Communication Network: Initialization, Push, Relabel, and Comparative Analysis.

We execute Push-Relabel on the canonical benchmark network documented in the notes:

Vertices: {S, A, B, T}, with |V| = 4.
Capacities: c(S, A) = 10, c(S, B) = 5, c(A, T) = 10, c(B, T) = 10.

Step-by-Step Step Execution:

Step 1: Initialization
  • Set height $h(S) = |V| = 4$. For intermediate and sink nodes: $h(A) = h(B) = h(T) = 0$.
  • Initialize preflow from $S$: saturate all outgoing edges from source.
  • $f(S, A) = 10 \implies e(A) = 10$, residual $c_f(S,A) = 0$, reverse residual $c_f(A, S) = 10$.
  • $f(S, B) = 5 \implies e(B) = 5$, residual $c_f(S,B) = 0$, reverse residual $c_f(B, S) = 5$.
  • Excess vector: $e(A) = 10, e(B) = 5, e(T) = 0$. Active nodes: $\{A, B\}$.
Step 2: Processing Active Node $A$

To push to neighbor $T$, we must satisfy $h(A) = h(T) + 1$. Currently $h(A) = 0$ and $h(T) = 0$. Push is illegal ($0 \neq 0 + 1$).

Relabel $A$: $h(A) = 1 + \min \{ h(T) \} = 1 + 0 = 1$.

Now $h(A) = 1 > h(T) = 0$. Push condition met.

Push$(A, T)$: $\Delta = \min(e(A), c_f(A, T)) = \min(10, 10) = 10$.

Updated: $e(A) = 10 - 10 = 0$, $e(T) = 10$, $f(A, T) = 10$. Node $A$ is now inactive.

Step 3: Processing Active Node $B$

Check Push$(B, T)$: $h(B) = 0$ and $h(T) = 0$. Push condition fails.

Relabel $B$: $h(B) = 1 + \min \{ h(T) \} = 1 + 0 = 1$.

Push$(B, T)$: $\Delta = \min(e(B), c_f(B, T)) = \min(5, 10) = 5$.

Updated: $e(B) = 5 - 5 = 0$, $e(T) = 10 + 5 = 15$, $f(B, T) = 5$. Node $B$ is now inactive.

Step 4: Termination

Active nodes in $V \setminus \{S, T\}$ is empty ($\emptyset$). The algorithm terminates.

Final Maximum Flow = $f(A, T) + f(B, T) = 10 + 5 = 15\text{ units}$.

Efficiency & Large Network Trade-offs:

Advantages: Excellent for dense, high-concurrency topologies where finding long global paths creates severe lock contention. Runtime is immune to edge capacity magnitudes ($\mathcal{O}(V^3)$ vs Ford-Fulkerson's capacity dependence).
Limitations: Excess flow temporarily trapped in subgraphs may require successive relabels up to $2|V|-1$ to route back to $S$, inducing computational overhead on simple sparse chains where BFS search is trivial.

Question 7

Explain the Capacity Scaling Algorithm for Minimum Cost Flow.

The Capacity Scaling Algorithm solves the Minimum Cost Flow problem by restricting augmentations to paths capable of transmitting significant flow, eliminating the pitfall of taking exponentially many tiny 1-unit steps.

Key Principles & Phases:

  1. Scaling Parameter ($\Delta$): Let $U = \max_{(u,v) \in E} c(u, v)$ be the maximum edge capacity. The algorithm initializes $\Delta = 2^{\lfloor \log_2 U \rfloor}$ (the largest power of 2 not exceeding $U$).
  2. $\Delta$-Residual Network ($G_f(\Delta)$): In each phase, the algorithm constructs the sub-network containing only residual edges whose available capacity is at least $\Delta$: $$E_f(\Delta) = \{ (u, v) \in E_f \mid c_f(u, v) \ge \Delta \}$$
  3. Shortest Augmenting Path in $G_f(\Delta)$:Using Dijkstra's algorithm (with node potentials $\pi(i)$) or Bellman-Ford, it locates the minimum-cost directed path from source to sink in $G_f(\Delta)$ and pushes flow.
  4. Scaling Down: When no augmenting path exists with capacity $\ge \Delta$, the parameter is halved: $$\Delta \leftarrow \lfloor \Delta / 2 \rfloor$$ The process repeats until $\Delta = 1$, at which point all remaining standard augmentations complete.
Time Complexity: The algorithm finishes in $\mathcal{O}(\log U)$ scaling phases. The overall running time is weakly polynomial: $\mathcal{O}(E \log U (E + V \log V))$, dramatically faster than unscaled cycle canceling.
Question 8

Cycle-Canceling Algorithm: Identifying Negative Cycles, Residual Updates, and Cost Optimization.

We work through the classic problem solved in the class notes (Week 8, Feb 16–22):

Problem Specification: Transport $4\text{ units}$ of flow from $S$ to $T$.
Edges $(c, \text{cost})$: $S \to A\,(4, 3)$, $A \to T\,(4, 2)$, $S \to B\,(4, 2)$, $B \to T\,(4, 4)$, and cross-link $A \to B\,(4, -3)$.
Step 1: Establish Initial Feasible Flow

Send 4 units along the upper route $S \to A \to T$.

  • $f(S, A) = 4$, $f(A, T) = 4$. Flow = 4 units (satisfies demand).
  • Cost per unit along $S \to A \to T = 3 + 2 = 5$.
  • Initial Total Cost $= 4 \times 5 = \mathbf{20}$.
Step 2: Construct Residual Graph $G_f$

Flow passing forward creates reverse edges with negated costs:

  • Forward $A \to T$ is full $\implies$ reverse edge $T \to A$ with $c_f = 4$, $\text{cost} = -2$.
  • Forward $S \to A$ is full $\implies$ reverse edge $A \to S$ with $c_f = 4$, $\text{cost} = -3$.
  • Unused edge $A \to B$ with $c_f = 4$, $\text{cost} = -3$.
  • Unused edge $B \to T$ with $c_f = 4$, $\text{cost} = 4$.
  • Unused edge $S \to B$ with $c_f = 4$, $\text{cost} = 2$.
Step 3: Identify Negative Cost Cycle

Trace cycle $C = A \to B \to T \to A$ in the residual graph:

  • Edge $A \to B$: $\text{cost} = -3$
  • Edge $B \to T$: $\text{cost} = +4$
  • Reverse edge $T \to A$: $\text{cost} = -2$
  • Cycle Cost: $(-3) + 4 + (-2) = \mathbf{-1} < 0$ (Negative Cycle Detected!).
Step 4: Push Flow around Cycle

Capacity of cycle $\delta = \min(c_f(A, B), c_f(B, T), c_f(T, A)) = \min(4, 4, 4) = 4\text{ units}$.

Augmenting 4 units around $A \to B \to T \to A$ effectively cancels 4 units on $A \to T$ and establishes 4 units on $A \to B$ and $B \to T$.

New Routing: $S \to A \to B \to T$

Cost per unit: $\text{cost}(S, A) + \text{cost}(A, B) + \text{cost}(B, T) = 3 + (-3) + 4 = 4$.

Final Total Cost: $4 \times 4 = \mathbf{16}$.

Cost Savings: $20 - 16 = \mathbf{4}$. Since no negative cycles remain in $G_f$, the solution is strictly minimal.

Capacity Scaling Algorithm: Step-by-Step 10-unit Minimum Cost Flow Execution.

Network Edges (capacity, cost):
S &to; A (8, 2), S &to; B (6, 3), A &to; B (4, 1),
A &to; T (5, 4), B &to; T (7, 2), B &to; A (2, 3)
Target Flow required from S to T = 10 units.

Phase 1: Scaling Factor $\Delta = 8$

Edges with capacity $\ge 8$: only $S \to A$ (cap 8). But sink $T$ cannot be reached with edges $\ge 8$ (max edge to $T$ is $B \to T$ of cap 7, $A \to T$ is 5). No augmenting path exists in $G_f(8)$. Flow pushed = 0.

Edges in $G_f(4)$: $S \to A\,(8, 2)$, $S \to B\,(6, 3)$, $A \to B\,(4, 1)$, $A \to T\,(5, 4)$, $B \to T\,(7, 2)$.

Evaluate available paths from $S$ to $T$ in $G_f(4)$:

  • Path 2 ($S \to A \to B \to T$): Cost $= 2 + 1 + 2 = 5$. Capacity bottleneck $= \min(8, 4, 7) = 4$.
  • Path 3 ($S \to A \to T$): Cost $= 2 + 4 = 6$.

Target remaining flow: $10 - 8 = 2$ units.

Examine $G_f(2)$ paths with $c_f \ge 2$:

  • Edge $S \to B$ has residual $c_f = 6$.
  • Edge $B \to T$ has residual $c_f = 3 \ge 2$.
  • Path $S \to B \to T$: Cost $= 3 + 2 = 5$. Bottleneck $= \min(6, 3) = 3$.

Augmentation 3: Push remaining needed $2$ units along $S \to B \to T$.

Residual changes: $c_f(S, B) = 6 - 2 = 4$, $c_f(B, T) = 3 - 2 = 1$. Total flow reached $= 10$ units.

  • $4\text{ units}$ via $S \to A \to B \to T$: cost $= 4 \times (2 + 1 + 2) = 4 \times 5 = 20$.
  • $4\text{ units}$ via $S \to A \to T$: cost $= 4 \times (2 + 4) = 4 \times 6 = 24$.
  • $2\text{ units}$ via $S \to B \to T$: cost $= 2 \times (3 + 2) = 2 \times 5 = 10$.

Total Minimum Cost = $20 + 24 + 10 = \mathbf{54}$.

Question 10

Data Center Multi-Resource Allocation via Flow Networks: Formulation, Bottleneck Identification, and Maximum Feasible Workload.

Allocating heterogeneous compute resources (CPU cores, RAM gigabytes, and network bandwidth) across competing server applications is modeled via a Layered Bipartite Flow Network.

Network Construction:

  1. Supersource ($S$): Connects to every application node $A_i$ with capacity equal to the application's demand workload $D_i$.
  2. Application Layer ($A_i$): Connects to compatible physical server resource slots $S_{j, r}$ (where $r \in \{\text{CPU}, \text{RAM}, \text{BW}\}$).
  3. Node-Splitting for Multi-Resource Constraints: To ensure a server $j$ does not exceed its physical capacity along any dimension, server nodes are subdivided into distinct resource-capacity vertices with internal gadget edges: $$c(\text{Server}_j^{\text{CPU\_in}}, \text{Server}_j^{\text{CPU\_out}}) = \text{Total CPU Cores of Server } j$$
  4. Supersink ($T$): Connects each server's egress to $T$ with link capacities matching host interface line rates.

Bottleneck Detection & Max Feasible Allocation:

Applying the Max-Flow Min-Cut Theorem, the maximum feasible allocation equals the capacity of the minimum cut $(S^*, T^*)$. Any edge $(u, v)$ crossing the minimum cut with $u \in S^*, v \in T^*$ having zero residual capacity represents a hard bottleneck resource (e.g., exhausted RAM on Server 2 or saturated uplink bandwidth on Server 1).

Question 11

Dynamic Connectivity on Graph with Edges (1,2), (2,3), (3,4), (4,5): Edge Deletion of (3,4) and Connectivity Status.

Consider an undirected graph $G = (V, E)$ where $V = \{1, 2, 3, 4, 5\}$ and edges $E = \{(1,2), (2,3), (3,4), (4,5)\}$. This is a simple linear chain (path graph).

1. Connectivity Status Before Edge Deletion:

Path: $1 - 2 - 3 - 4 - 5$. Connected components $= 1$.

$\text{Connected}(1, 5) = \mathbf{True}$. A direct simple path of length 4 connects vertex 1 and 5.

2. Dynamic Edge Update (Delete Edge (3, 4)):

Edge $(3, 4)$ is a bridge (cut edge) in the tree topology. Removing $(3, 4)$ decomposes the graph into two disjoint connected components:

$$\mathcal{C}_1 = \{1, 2, 3\} \quad \text{and} \quad \mathcal{C}_2 = \{4, 5\}$$
3. Connectivity Status After Edge Deletion:

Query $\text{Connected}(1, 5)$: Vertex $1 \in \mathcal{C}_1$ and vertex $5 \in \mathcal{C}_2$. Since $\mathcal{C}_1 \cap \mathcal{C}_2 = \emptyset$ and no alternate paths exist:

Vertices 1 and 5 are NOT connected (Disconnected / False).

Algorithm Note (as covered in the notes): While a standard Disjoint Set Union (DSU) cannot perform edge deletions without rebuilds, fully dynamic connectivity data structures (like Euler Tour Trees or Link-Cut Trees) update the tree cut in $\mathcal{O}(\log n)$ or $\mathcal{O}(\log^2 n)$ time.

Question 12

Multi-Stream Bandwidth Allocation between Source and Destination Servers: Congestion Avoidance and Flow Maximization.

During peak load, multiple data streams originate from candidate source servers $\{S_1, S_2, \dots\}$ destined for destination nodes $\{T_1, T_2, \dots\}$ across a shared switch fabric.

Multi-Source Multi-Sink Reduction Formulation:

1. Super-Source ($S^*$): Construct an artificial super-source $S^*$. Add directed edges from $S^*$ to each source server $S_i$ with capacity $c(S^*, S_i) = \text{Maximum generation bandwidth of } S_i$.

2. Super-Sink ($T^*$): Construct an artificial super-sink $T^*$. Add directed edges from each destination server $T_j$ to $T^*$ with capacity $c(T_j, T^*) = \text{Maximum ingestion bandwidth of } T_j$.

3. Core Switch Capacities: Every physical link $(u, v)$ has an inviolable capacity $c(u, v)$ representing its physical port bandwidth limit.

Preventing Congestion & Maximizing Data Transfer:

Applying Dinic's Algorithm or Push-Relabel guarantees two mathematical properties:

  • Zero Congestion (Capacity Adherence): For every link, $0 \le f(u, v) \le c(u, v)$. No network link is ever oversubscribed.
  • Zero Packet Drop (Flow Conservation): At every intermediate switch $u$, $\sum f_{in}(u) = \sum f_{out}(u)$, ensuring buffers do not overflow.
  • Maximized System Utilization: The algorithm finds the global maximum volume of concurrent data streams without heuristic trial-and-error.

MODULE 2: Strongly Connected Components & Graph Traversals

12 Questions
Question 1

What is a strongly connected component? Give an example.

A Strongly Connected Component (SCC) of a directed graph $G = (V, E)$ is a maximal subgraph $G' = (V', E')$ such that every vertex in $V'$ is mutually reachable from every other vertex in $V'$. That is, for every pair of vertices $u, v \in V'$, there exists a directed path from $u$ to $v$ and a directed path from $v$ to $u$.

Maximality implies that no additional vertex from $V \setminus V'$ can be added to the set without violating this mutual reachability property.

Example from Course Notes (Module 2, Page 49):

Consider directed edges $A \to B$, $B \to C$, and $C \to A$.

- Path $A \to B \to C$: $A$ can reach both $B$ and $C$.
- Path $B \to C \to A$: $B$ can reach both $C$ and $A$.
- Path $C \to A \to B$: $C$ can reach both $A$ and $B$.
Since mutual reachability holds for all pairs, the set $\mathbf{\{A, B, C\}}$ forms an SCC.

Question 2

Apply the concept of strongly connected components to a directed graph and identify whether a given set of vertices forms an SCC, with justification.

To rigorously verify whether a candidate vertex subset $S \subseteq V$ constitutes a Strongly Connected Component, two conditions must be verified:

Condition 1: Mutual Reachability

For every ordered pair $(u, v)$ where $u, v \in S$, there must exist a directed path $u \leadsto v$. A single directed disconnect proves that $S$ is not strongly connected.

Condition 2: Maximality

No outside vertex $w \in V \setminus S$ can be added such that $S \cup \{w\}$ is also mutually reachable. If a mutual cycle extends to $w$, then $S$ is only a strongly connected subset, not a component.

Method of Justification: Perform a localized DFS/BFS from each vertex in $S$ within the subgraph, or compute the transitive closure matrix restricted to $S$. If all entries $M[u][v] = 1$, and all edges exiting $S$ are unidirectional cross-component edges with no return paths, $S$ is confirmed as an SCC.

Question 3

Given edges 1&to;2, 2&to;3, 3&to;1, 3&to;4, and 4&to;5: Does {1, 2, 3} form an SCC? Justification by path verification.

Graph: $V = \{1, 2, 3, 4, 5\}$, Directed Edges: $1 \to 2$, $2 \to 3$, $3 \to 1$, $3 \to 4$, $4 \to 5$.

1. Pairwise Reachability within Set $S = \{1, 2, 3\}$:
  • From Vertex 1: Path to 2 is $1 \to 2$. Path to 3 is $1 \to 2 \to 3$. (Reachable)
  • From Vertex 2: Path to 3 is $2 \to 3$. Path to 1 is $2 \to 3 \to 1$. (Reachable)
  • From Vertex 3: Path to 1 is $3 \to 1$. Path to 2 is $3 \to 1 \to 2$. (Reachable)

Thus, all vertices in $\{1, 2, 3\}$ are mutually reachable through directed cycle $1 \to 2 \to 3 \to 1$.

2. Maximality Check:
  • Check Vertex 4: Vertex 3 can reach 4 ($3 \to 4$). But node 4 has only an outgoing edge to 5 ($4 \to 5$) and no path back into $\{1, 2, 3\}$. Thus $4 \not\leadsto 1$. Vertex 4 cannot be added.
  • Check Vertex 5: Reached from 4 ($4 \to 5$). Out-degree of 5 is 0. Vertex 5 cannot reach any node in $\{1, 2, 3\}$.
Conclusion: Yes, {1, 2, 3} forms an SCC. It satisfies both mutual reachability and maximality.
Question 4

Kosaraju's Algorithm on Edges 1&to;2, 2&to;3, 3&to;1, 3&to;4, 4&to;5, and 5&to;4: First DFS, Transpose Graph, Second DFS, and SCC List.

Graph: $V = \{1, 2, 3, 4, 5\}$ with edges $1 \to 2, 2 \to 3, 3 \to 1, 3 \to 4, 4 \to 5, 5 \to 4$.

Step 1: First DFS on Original Graph $G$ (Finishing Time Stack)

Start DFS from Vertex 1:

  • Visit $1 \implies$ go to neighbor $2$.
  • Visit $2 \implies$ go to neighbor $3$.
  • Visit $3 \implies$ has neighbors $1$ (already visited) and $4$. Move to $4$.
  • Visit $4 \implies$ go to neighbor $5$.

Step 2: Construct the Transpose Graph $G^T$

Reverse the direction of every directed edge in $G$:

$G^T$ Edges: 2 &to; 1, 3 &to; 2, 1 &to; 3, 4 &to; 3, 5 &to; 4, 4 &to; 5.

We pop nodes from the stack order: $1, 2, 3, 4, 5$.

  • Pop 1: Start $\text{DFS}_{G^T}(1)$.
    From 1, traverse edge $1 \to 3$.
    From 3, traverse edge $3 \to 2$.
    From 2, traverse edge $2 \to 1$ (already visited).
    From 3, edge to 4 exists in original, but in $G^T$ the edge is $4 \to 3$ (incoming, cannot leave).

  • Pop 2: Already visited $\implies$ Skip.
  • Pop 3: Already visited $\implies$ Skip.

$\mathbf{\text{SCC}_1 = \{1, 2, 3\}}$
$\mathbf{\text{SCC}_2 = \{4, 5\}}$
Question 5

Define Eulerian path. What are the necessary conditions for its existence?

An Eulerian Path (or Euler trail) in a graph is a walk that visits every edge of the graph exactly once. Vertices may be revisited multiple times.

An Eulerian Circuit is an Eulerian path that starts and terminates at the same vertex.

Necessary and Sufficient Conditions (Euler's Theorem for Undirected Graphs):

Traversing Object Connectivity Requirement Degree Requirement
Eulerian Circuit All vertices with non-zero degree belong to a single connected component. Every vertex has an even degree ($\text{deg}(v) \pmod 2 = 0 \quad \forall v \in V$).
Eulerian Path (Open Trail) All vertices with non-zero degree belong to a single connected component. Exactly two vertices have odd degree, while all remaining vertices have even degree. (The path starts at one odd vertex and ends at the other).

Question 8

Describe Tarjan's Algorithm for finding strongly connected components.

Tarjan's Algorithm finds all strongly connected components of a directed graph in a single Depth-First Search (DFS) pass with linear time complexity $\mathcal{O}(V + E)$.

Four Fundamental Core Concepts (from Course Notes, Pages 50–51):

1. Discovery Time ($\text{disc}[u]$):

An integer timestamp recording exactly when vertex $u$ is first discovered during the DFS traversal.

2. Low-Link Value ($\text{low}[u]$):

The smallest discovery time reachable from $u$ through its DFS subtree and at most one back-edge to an active stack vertex.

3. Exploration Stack:

Maintains the active search path. Vertices stay on the stack until an entire SCC has finished exploring.

4. Root of an SCC ($\text{disc}[u] == \text{low}[u]$):

When DFS unwinds to a vertex where discovery equals low-link, $u$ is the anchor/root of an SCC. Nodes are popped until $u$ is removed.

Low-Link Update Rules:

For each outgoing edge $(u, v)$:

1. If $v$ is unvisited: recursively call DFS$(v)$, then backtrack: $$\text{low}[u] = \min(\text{low}[u], \text{low}[v])$$

2. If $v$ is already visited and currently on Stack (Back Edge): $$\text{low}[u] = \min(\text{low}[u], \text{disc}[v])$$

Question 11

What are dynamic connectivity algorithms? Explain their significance.

Dynamic Connectivity Algorithms maintain information about the connected components of a graph whose edge topology undergoes online insertions and deletions over time, answering queries of the form $\text{Connected}(u, v)$ efficiently without recomputing from scratch.

Three Classes of Dynamic Connectivity (from Notes Page 81):

1. Incremental

Edges are strictly added over time. Solved optimally via Disjoint Set Union (DSU / Union-Find) with near-constant amortized time $\mathcal{O}(\alpha(n))$ per query.

2. Decremental

Edges are strictly deleted from an initially complete graph. Requires specialized tree structures to efficiently detect when bridges break components.

3. Fully Dynamic

Both insertions and deletions of edges are supported in arbitrary interleaved sequences.

Computational Significance:

Re-running complete BFS/DFS after every link event costs $\mathcal{O}(V + E)$ time per update—completely impractical for high-frequency telecommunications switches, real-time social networks, or distributed cloud fabrics. Advanced data structures like Holm-de Lichtenberg-Thorup (HDT), Link-Cut Trees, and Euler Tour Trees maintain spanning forests supporting fully dynamic updates in $\mathcal{O}(\log^2 V)$ or $\mathcal{O}(\log V)$ time.

A Condensation Graph $G^{\text{SCC}} = (V^{\text{SCC}}, E^{\text{SCC}})$ contracts each strongly connected component into a single representative meta-vertex. Directed edges exist between meta-vertices if and only if there exists at least one directed edge between their constituent vertices in the original graph.

  • Meta-Edges: $E^{\text{SCC}} = \{(C_1, C_2)\}$.
Condensation Graph (Directed Acyclic Graph - DAG)

Fundamental Mathematical Property: The condensation graph $G^{\text{SCC}}$ is guaranteed to be a Directed Acyclic Graph (DAG). If it contained any directed cycle, all meta-nodes on that cycle would merge into one larger SCC, contradicting maximality.
